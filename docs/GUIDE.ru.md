# CookieGuard — полное руководство

Коротко о программе и установка — в [README](../README.ru.md). Здесь — как
устроена каждая часть, что она видит и где её пределы.

## Установка

Запустить **Setup.cmd** и подтвердить запрос прав администратора.

Установщик соберёт `CookieGuard.exe`, положит программу в
`C:\Program Files\CookieGuard`, заведёт ярлык в меню «Пуск» и зарегистрирует
её в «Приложениях и возможностях» — удаляется потом как любая обычная
программа.

Требуется Windows 10/11 и PowerShell 5.1 (входит в систему). Больше ничего
ставить не нужно: `.exe` собирается компилятором C# из .NET Framework, который
уже есть в Windows.

**Почему в Program Files.** Туда нельзя писать без прав администратора. Значит,
вредонос, работающий от обычного пользователя, не сможет подменить сам
инструмент защиты. Рабочие данные при этом живут отдельно, в
`C:\ProgramData\CookieGuard`, и тоже закрыты от записи обычным пользователям —
иначе можно было бы вытащить файл из карантина или самому себе выписать
доверие.

### Без установки

Можно просто распаковать папку и запустить `CookieGuard.exe` оттуда —
переносной режим. Тогда все данные (журналы, карантин, эталон) остаются рядом
с программой, и в системе ничего не создаётся. Для постоянной защиты этот
режим не годится: папку можно удалить или подменить.

### Удаление

Параметры → Приложения → CookieGuard → Удалить. Либо `scripts\Uninstall.ps1`.
Удаление снимает постоянную защиту, выключает аудит, возвращает DNS к прежним
настройкам и убирает ярлыки. Журналы, отчёты, улики и карантин **остаются** —
удалять улики вместе с программой неправильно. Чтобы снести и их:
`scripts\Uninstall.ps1 -RemoveData`.

## Что видит CookieGuard

ESET и Defender ищут известные вредоносные файлы и отвечают на вопрос
«этот файл — вирус?».

CookieGuard отвечает на другие вопросы:

- **Кто прикасался к файлам cookie?** Не «вирус ли это», а список программ с
  точным временем, PID, тем, что именно они делали (читали содержимое или
  меняли права), и командной строкой. Браузер в этом списке ожидаем. Остальное — нет.
- **Как запущен сам браузер?** Современная кража часто не трогает файл вовсе:
  браузер запускают с отладочным портом и забирают cookie уже расшифрованными.
- **Что в системе настроено не так?** Исключения антивируса, подменённый
  автозапуск, прокси, чужой корневой сертификат, расширение с правом читать
  cookie на всех сайтах, скрипт в автозапуске Adobe. Это не вирусы — поэтому
  антивирус молчит. А уводят сессии чаще всего именно через это.

Находит, объясняет и исправляет — с откатом каждого шага. Содержимое cookie и паролей он не читает
никогда — только смотрит, кто к ним лезет.

## Как устроено окно

Слева столбец разделов, справа страница — как в «Параметрах» Windows 11.
Это не подражание ради подражания: человек, открывший программу после взлома,
не должен вдобавок разбираться, где у неё что.

| Раздел | Что показывает |
|---|---|
| **Обзор** | Состояние аудита, Defender, браузеров и итог последней проверки |
| **Защита** | Переключатели постоянной работы: аудит, журнал запусков, сторож, эталон, VirusTotal, фильтрующий DNS |
| **Монитор** | Живая лента: обращения к cookie, запуск подозрительных программ, копии баз |
| **Находки** | Результат полной проверки по 12 разделам |
| **Процессы** | Все процессы с оценкой риска и причинами |
| **Расширения** | Расширения браузеров, их права и доступ к cookie |
| **Автозапуск** | Реестр, папки автозагрузки, задачи, службы |
| **Запуски** | История запуска программ — чтобы опознать мелькнувшее окно |
| **Карантин** | Обратимо спрятанные файлы |
| **Доверенные** | То, про что вы уже разобрались, и насколько широко действует доверие |
| **Журнал** | Текстовый лог по дням |

Щелчок по строке открывает **разбор справа**: подробности и всё, что с этой
строкой можно сделать — **Доверять**, **В проводнике**, **Искать в сети**,
**VirusTotal**, **Спросить у ИИ** (готовит вопрос с уликами и кладёт в буфер),
**Копировать**, а для необратимого — **Завершить процесс**, **В карантин**,
**Обезвредить**. Кнопка, для которой у строки нет данных, гаснет.

То же меню открывается **правой кнопкой прямо на строке**.

Все окна вопросов — свои. Системные `MessageBox` и `InputBox` не используются:
в светлой теме Windows они выглядят рядом с программой как чужое окно, влезшее
в разговор, — и ровно в тот момент, когда спрашивают согласие на необратимое.

## Исправить всё

В «Находках» и на обзоре есть кнопка **Исправить всё**. Она собирает в один
список всё, что программа умеет исправить сама, и показывает его с галочками:
снимите те, что оставили намеренно. Каждое исправление обратимо — прежнее
значение сохраняется в папке `undo`. Опасные действия (карантин, удаление
папок) в этот список не попадают: их делают по одному, глядя на находку.
Отключённые вами обновления Windows и живые программы в автозапуске по
умолчанию не отмечены; мёртвые записи автозапуска — отмечены.

## Корневые сертификаты

Для каждого постороннего корневого сертификата программа объясняет, что это
скорее всего такое (антивирус, отладочный прокси, драйвер USB-устройства,
программа на этом компьютере) и **может ли он на самом деле читать защищённый
трафик**. Сертификаты, разрешённые только для подписи кода (например, те, что
ставит Zadig/libwdi для загрузчиков микроконтроллеров), трафик читать не могут,
и тревоги по ним нет. Для остальных есть два исправления: **Ограничить
назначение** (сертификат остаётся, но для сайтов Windows его больше не
принимает) и **Убрать** (с копией в `undo`).

## Свой блокировщик рекламы

Фильтрующий DNS (AdGuard DNS и подобные) не видит рекламу, если браузер ходит
через свой защищённый DNS или через прокси — например, Karing. Поэтому
у CookieGuard есть свой блокировщик: расширение для Chrome, Edge и Brave
в папке `adblock`.

- **Сетевые запросы режет сам браузер** по правилам из файлов
  (declarativeNetRequest). Расширение ваших запросов не видит: у него нет прав
  webRequest, cookies и history. Политика безопасности его страниц
  (`connect-src 'self'`) запрещает ему ходить в сеть вообще.
- **На странице** оно только прячет рекламные блоки. На YouTube вырезает
  рекламу из ответа сервера и проматывает то, что проскочило.
- **Встроенные правила** — около сотни рекламных сетей, в том числе российских.
  Кнопка **Обновить списки** скачивает выбранные списки (по умолчанию
  EasyList, RuAdList, EasyPrivacy и список Peter Lowe; в меню ⋯ — **Выбрать
  списки**: AdGuard, Fanboy's Annoyance, Anti-Adblock, а также **свой список по
  адресу**) и переводит их в правила браузера: берутся только адреса и
  CSS-селекторы, скриптлеты и прочий код из списков отбрасываются.
- **Общие правила скрытия** (`##.ad-banner` без сайта — их в списках десятки
  тысяч) разложены по классам и id: страница сообщает расширению, какие классы
  и id в ней есть, и получает только подходящие правила.
- **Обновляется само.** Программа при каждом запуске приводит папку расширения
  к своей версии и ставит отметку сборки; расширение раз в минуту сверяет её и
  перезагружается само. Нажимать «Обновить» на странице расширений не нужно.
- **Защита → Блокировщик рекламы → Подключить к браузеру**: программа кладёт
  расширение в `%LOCALAPPDATA%\CookieGuard\adblock-ext`, открывает страницу
  расширений и кладёт путь в буфер обмена. Остаётся включить «Режим
  разработчика» и нажать «Загрузить распакованное» — подключить расширение без
  человека браузер не даёт, и обходить эту защиту программа не будет.
- В значке расширения — выключить блокировку на сайте; в настройках — свои
  домены, свои правила скрытия и сайты-исключения.

## Расширения: вторая проверка

Право читать cookie на всех сайтах есть и у вредоноса, и у Adobe Acrobat. Чтобы
отличать одно от другого, программа спрашивает магазин Chrome/Edge о критичных
расширениях: есть ли оно там и сколько у него пользователей. Наружу уходит
только номер расширения. Массовое расширение из магазина опускается до
заметки, снятое с публикации — остаётся критичным. Ответы хранятся неделю в
`state\ext-verdicts.json`. Одно расширение в нескольких профилях браузера —
одна строка.

## Доверие ко всему, что запускает программа

Помощники вроде Claude сами запускают cmd, node и PowerShell — каждый раз с
новым номером процесса. «Доверять» на таком процессе предлагает область
**«Всё, что запускает claude.exe»**: она держится на подписи издателя и
действует на всю цепочку потомков. После «Доверять» все уже собранные таблицы
перепроверяются сразу — нажимать «Проверить систему» заново не нужно.

## Проверка файла или папки

Файл, папку или архив можно просто бросить в любое место главного окна — оно
само откроет раздел **03 Проверка файлов**. Туда же ведёт кнопка **Проверить
файл или папку**. Дальше программа разбирается сама:

- обходит папку и **решает, что вообще стоит проверять**: программы, сценарии и
  документы с кодом — да; картинки, музыка и текст — нет;
- **распаковывает архивы** во временную папку и смотрит внутрь, в том числе в
  архив внутри архива;
- **спрашивает пароль**, если архив зашифрован (включая `.7z` со скрытыми
  именами файлов). Пароль нужен только для распаковки: он не сохраняется и
  никуда не передаётся;
- **не тратит запросы** на то, у чего действующая подпись известного издателя,
  и на то, что вы уже пометили доверенным.

Наружу уходит только отпечаток SHA-256. Содержимое файла не отправляется
никогда: загрузка файла на VirusTotal — это публикация, его увидят другие.

Для `.7z`, `.rar` и архивов под паролем нужен установленный
[7-Zip](https://www.7-zip.org/); обычный `.zip` программа открывает сама.

> Перетаскивание в окно, запущенное от администратора, Windows по умолчанию
> запрещает. Программа открывает для своего окна ровно три нужных сообщения,
> но если перетаскивание всё же не сработает — есть кнопка «Выбрать файлы».

## Автозащита: один переключатель на всё

Раздел **Защита** → **Автозащита**. Один переключатель включает всё
наблюдение сразу, а кнопка **Что включено ▾** раскрывает список частей с
живым состоянием каждой — не «защита включена», а что именно работает:

| Часть | Что даёт |
| --- | --- |
| Сторож при старте Windows | работает от SYSTEM без окна, даже когда никто не вошёл |
| Наблюдатель | раз в минуту поднимает сторожа, если его убили; возвращает снятую задачу сторожа |
| Аудит доступа к файлам | Windows записывает, какая программа открыла базу cookie |
| Все базы cookie и паролей | всех профилей всех браузеров; новый профиль и пересозданный файл берутся сами |
| Журнал запуска программ | событие 4688 с командной строкой |
| Слежение за hosts | что поменяли и кто (см. ниже) |
| Теневой путь | куда соединяется тот, кто трогал cookie (см. ниже) |
| Журнал безопасности 256 МБ | чтобы события не затирались раньше, чем их прочтут |
| Журнал событий на диске | тревоги переживают перезапуск, перезагрузку и обновление |

**Помнит.** Выбор хранится в `state\settings.json`, а не в памяти окна.
Монитор окна тоже помнит, включали ли его: при следующем запуске он
включается сам.

**Сам чинит.** Сторож раз в минуту проверяет каждую часть и включает обратно
то, что выключили, — с записью в журнал и всплывающим уведомлением. Пока
автозащита включена, отдельные переключатели ниже неактивны: выключить одну
часть нельзя, сторож всё равно вернул бы её.

**Журнал не теряется.** Каждая тревога пишется строкой JSON в
`logs\events-ГГГГ-ММ.jsonl`. Окно при запуске показывает прошлое, а пока
работает сторож — не опрашивает систему само, а читает его записи вживую:
одна летопись, без двойных тревог. Раздел «Журнал» показывает последние семь
дней, а не только сегодня.

### Что было не так раньше

- Сторож работает от SYSTEM, и для него «папка браузера» — это профиль самой
  системы, где браузеров нет. **Фоновый сторож не видел ни одного чтения
  cookie**, а его «поднять аудит обратно» не находило файлов. Теперь под
  SYSTEM перебираются настоящие профили из реестра.
- Наблюдатель не создавался ни разу: задача с повтором `[TimeSpan]::MaxValue`
  Windows 10 отвергает, а ошибка уходила в предупреждение.
- Журнал писали двое (сторож и окно), и строка второго молча пропадала, если
  файл был занят. Теперь запись идёт только дозаписью с общим доступом и
  повтором.
- Больше 400 событий за цикл — и всё, кроме 400 самых новых, пропадало
  навсегда. Теперь события читаются по порядку, с самого старого.
- «Журнал запуска программ» был кнопкой без состояния и выглядел
  выключенным, а выключение аудита cookie гасило его заодно.
- Сторож кричал «защиту Windows ВЫКЛЮЧИЛИ» при каждом старте на машине под
  ESET. Теперь тревога — только если нет и другого работающего антивируса.

## hosts: что поменяли и кто

Одна строка в `hosts` — и банк, почта или обновления антивируса открываются
там, где скажет вирус. Раньше проверка видела лишь «перенаправлений столько-то»
и не отличала обход блокировки от подмены. Теперь:

- копия файла хранится в `state\hosts-snapshot.txt` и переживает перезагрузку:
  изменение, сделанное, пока программа не работала, тоже будет показано;
- изменение разбирается построчно: что добавлено, что убрано, в каком разделе
  (Zapret, CyberMania и другие подписывают свои разделы комментариями);
- на `hosts` и папку `etc` ставится аудит **записи** — Windows сама говорит,
  какая программа писала в файл (чтение не аудируется: его делает каждый запрос DNS);
- прежняя версия ложится в `evidence\…-hosts-before.txt`, из неё файл можно вернуть.

Как оценивается строка:

- **критично** — вход в аккаунты, банк, почта, крипта направлены на заданный
  вручную адрес;
- **внимание** — любой другой сайт на заданном вручную адресе; блокировка сайтов
  антивирусов, Windows Update, VirusTotal и GitHub (так вирус ослепляет защиту —
  и так же поступают «активаторы»);
- **заметка** — адрес из собственной сети сервиса (например, Telegram:
  `149.154.160.0/20` и другие его сети) — это обход блокировки, трафик идёт к
  самому Telegram; блокировка рекламы и телеметрии.

Раздел, в котором стоит строка, показывается как подсказка, а не как
оправдание: подписаться «Zapret» может и вирус. Ответ на вопрос «кто» даёт
журнал безопасности, а не комментарий в файле.

## Теневой путь: куда уходят cookie

Вор паролей делает три вещи: читает базу, складывает копию, отправляет. Первое
видно по аудиту, второе — по обходу копий. Третье раньше не видел никто.

- Программа, тронувшая cookie, и процесс с признаками вредоноса **10 минут под
  наблюдением в сети**: каждое их новое соединение — событие «ТЕНЕВОЙ ПУТЬ», с
  адресом, именем из кеша DNS и уликой.
- Соединения, открытые в момент чтения cookie, записываются в само событие.
- Любая посторонняя программа, соединяющаяся с **Telegram API, вебхуками
  Discord, файлообменниками** (gofile, transfer.sh, catbox, pastebin, ngrok…) и
  сервисами «узнай мой IP», — событие: это любимые каналы слива. Telegram,
  Discord, браузеры и программы известных издателей сюда не попадают; свою
  программу (неофициальный клиент, бот, прокси) можно пометить доверенной.
- Если программа идёт через локальный прокси (Karing, v2ray), видно «отправляет
  через прокси такой-то» и кто этот прокси.

Честно о пределах: это опрос раз в три секунды, а не перехват. Соединение
короче трёх секунд можно не застать, объём отправленного не виден, а за
локальным прокси конечный адрес не виден.

## Агенты-усы: восемь взглядов на cookie

Аудит файла видит, кто **открыл** базу. Но базу можно украсть, не открывая
её. Поэтому вокруг неё — независимые агенты, как усы клубники:

| Агент | С какой стороны смотрит |
| --- | --- |
| Аудит файла | кто открыл Cookies, Login Data, key4.db (события 4656/4663) |
| Приманка | ненастоящий профиль `Profile 99` в папке каждого браузера; браузер его не видит, вор, перебирающий профили, — читает. Чтение приманки — всегда кража |
| Отладочный порт | браузер с `--remote-debugging-port` или слушающий порт: так cookie забирают уже расшифрованными, не трогая файл (обход защиты Chrome 127+) |
| Ключ шифрования | кто читает `Local State`, где лежит ключ к cookie; вызовы DPAPI из командной строки |
| Теневые копии | `esentutl /vss`, `vssadmin create shadow`, чтение `HarddiskVolumeShadowCopy` — копия базы мимо блокировки и аудита |
| Внедрение | неподписанные библиотеки внутри процессов браузера |
| Сеть | теневой путь и каналы слива |
| hosts | подмена адресов |

Короткие запуски (esentutl работает долю секунды) агенты видят по журналу
запуска программ 4688, а не по опросу процессов. **Перекличка:** каждый агент
отмечается в `state\agents.json`; наблюдатель — отдельный процесс — сверяет
отметки и перезапускает сторожа, если агенты замолчали. Приманки убирает
выключение автозащиты.

## Сеть: десять контрольных точек

`lib\Network.ps1` оценивает каждое соединение по десяти точкам: подпись,
издатель, папка, имя в DNS, принадлежит ли адрес имени (или подменён в hosts),
не канал ли слива, напрямую или через прокси, возраст файла, VirusTotal,
доверие. Вердикт — их сумма: «норма», «проверить», «опасно».

## AppData

`lib\AppData.ps1` раскладывает AppData по полкам: чья папка (по подписи
программ внутри, а не по имени — `Roaming\Google` может оказаться Android
Studio), сколько весит, когда менялась, есть ли неподписанные программы и не
стартует ли из неё что-то с Windows. Обход всех ~360 папок — около 20 секунд.

## Четыре вещи, которые стоит включить

Всё это включает автозащита. По отдельности — так:

### 1. Аудит доступа к файлам

Переключатель «Аудит доступа к cookie» в разделе «Защита». Включает штатный механизм Windows и
ставит метку на `Cookies` и `Login Data` всех браузеров. После этого **ядро
Windows само** записывает каждое обращение. Подделать такую запись из обычной
программы нельзя.

Без этого монитор работает, но не видит, *кто* открыл файл.

### 2. Журнал запуска программ

Кнопка «Журнал запуска программ» в разделе «Защита». Включает событие 4688 вместе с командной строкой.
После этого любое мелькнувшее окно опознаётся: что запустилось, с какими
аргументами, кто родитель. Без него раздел показывает только Prefetch —
факт запуска без подробностей.

### 3. Эталон системы

Кнопка «Снять эталон». Запоминает автозапуск, расширения браузеров, скрипты
Adobe, корневые сертификаты, прокси и hosts, исключения антивируса и службы —
около двухсот объектов. Дальше кнопка «Сверить» показывает, что изменилось.

Это сильнее сигнатур и работает там, где они бессильны. Сигнатура отвечает на
вопрос «знаком ли нам этот вредонос». Эталон — на другой: «изменилось ли
что-то с тех пор, как было хорошо». Второй вопрос ловит и то, чего ещё нет ни
в одной базе: любой закрепившийся в системе вредонос обязан что-то изменить —
добавить автозапуск, подменить скрипт, поставить расширение, развернуть трафик.
Молча прижиться ему негде.

Снимайте эталон, когда уверены, что система в порядке, и обновляйте после
того, как сами что-то установили.

### 4. Своя база вердиктов (VirusTotal)

Собственных сигнатур здесь нет, и они не нужны: VirusTotal опрашивает разом
около семидесяти антивирусных движков. Программа считает SHA256, спрашивает
вердикт и **сохраняет его у себя** — со временем набирается местная база по
файлам именно этого компьютера, и повторные проверки идут мгновенно, без сети.

**Наружу уходит только отпечаток.** Файл не отправляется никогда: по SHA256
восстановить содержимое невозможно. Если VirusTotal файла не знает — он просто
ответит «не найдено».

Нужен бесплатный ключ: virustotal.com → регистрация → профиль → API key.
Ограничение бесплатного ключа — 4 запроса в минуту, 500 в сутки. Поэтому
проверяется не весь диск, а только то, что может оказаться закладкой:
неподписанные процессы, автозапуск, новые программы за 30 дней, скрипты Adobe.

Как читать результат: **1–2 детекта из 70 — почти всегда ложное срабатывание**
(особенно у самодельных программ, кейгенов, игровых модов). **5 и больше —
серьёзно.** «Неизвестен» значит «редкий», а не «чистый».

## Adobe: Premiere, After Effects и плагины

Отдельный раздел, потому что это отдельная дверь в систему.

У Premiere и After Effects есть ExtendScript — полноценный язык с доступом к
диску, к запуску программ и к сети. Скрипт из папки `Scripts\Startup`
запускается **сам при каждом старте программы**, лежит в обычном текстовом
`.jsx` и никакой подписи не имеет. Для антивируса это просто текст. Отсюда и
совпадение почерка: цель та же — cookie и пароли, меняется только способ
попасть внутрь. Вместо `.exe` — «бесплатный плагин».

Что проверяется:

- скрипты в папках автозапуска (`Startup`, `Shutdown`, `ScriptUI Panels`);
- скрипты там, куда можно писать без прав администратора;
- `.jsxbin` — скомпилированные, намеренно нечитаемые;
- внутри скриптов: `system.callSystem`, `$.evalFile`, `new Socket`,
  `XMLHttpRequest`, вызовы `cmd.exe`/`powershell`, сборка строк из кодов
  символов, большие блоки Base64, обращение к собственной папке автозапуска;
- **саморазмножение** — один и тот же скрипт в автозапуске нескольких программ
  (так ведёт себя червь, законные плагины так не ставятся);
- настройка «Allow Scripts to Write Files and Access Network»;
- `PlayerDebugMode` — режим загрузки неподписанных расширений, который включают
  установщики пиратских плагинов;
- сторонние расширения CEP в пользовательских папках.

Отбор намеренно строгий: сама Adobe привозит сотни своих `.js` (темы, jQuery,
сборки панелей). Они лежат в Program Files, сами не запускаются, и показывать
их все — значит сделать список нечитаемым.

**Что делать, если нашлось:**

1. Не удалять сразу — сначала посмотреть путь и вспомнить, какой плагин ставили.
2. Снять галку «Allow Scripts to Write Files and Access Network» — многие
   закладки сразу перестают работать.
3. Выключить `PlayerDebugMode`.
4. Подозрительный `.jsx` перенести в отдельную папку (не удалять — это улика),
   перезапустить Adobe, проверить, что всё работает.
5. Проверить SHA256 через VirusTotal.

**Как не поймать снова:** ставить плагины только с сайта автора или из Adobe
Exchange; относиться к «repack», «free», «crack» как к установщику с нагрузкой;
после установки любого плагина — проверять этот раздел.

## Безопасный сёрфинг без расширения

Строка **Безопасный сёрфинг** в разделе «Защита».

Блокировщик рекламы в виде расширения просит права «читать и менять все данные
на всех сайтах» — то есть ровно те, которыми уводят сессии. Получается, защита
от рекламы покупается самым опасным разрешением.

Фильтрующий DNS снимает эту плату: вредоносные и рекламные домены просто не
разрешаются в адрес, значит до браузера не доходят. Работает **во всей
системе**, а не только в браузере, и расширение становится не нужно.

Наборы на выбор: AdGuard DNS (реклама + слежка + вредоносное), AdGuard Family
(плюс взрослый контент), Quad9 и Cloudflare (только вредоносное, рекламу не
трогают). Прежние настройки сохраняются, кнопка «Вернуть как было» их
восстанавливает.

**Границы, которые надо знать:**

- страницу «Заблокировано CookieGuard» показать нельзя — браузер покажет
  обычную ошибку соединения. Уведомление даёт сторож, а не сама страница;
- косметику DNS не чинит: он не прячет блоки на странице, а не пускает запрос;
- если весь трафик идёт через VPN или прокси, имена могут разрешаться на его
  стороне, и системный фильтр будет обойдён. Кнопка **Проверить** это покажет.

## Доверенные: «я разобрался, больше не спрашивай»

Кнопка **Доверять** в разборе справа или в меню правой кнопки. Это главное лекарство от усталости от
тревог: если программа каждый день кричит «КРИТИЧНО» на расширение, которое вы
сами поставили и решили оставить, вы перестанете читать находки вообще — и
пропустите настоящую.

Доверять можно процессу/файлу, расширению браузера или конкретной находке.
Доверенное перестаёт попадать в находки, в монитор и в уведомления, но остаётся
видимым в разделе **Доверенные** вместе с причиной, которую вы записали.

### Область доверия

Программа спрашивает не только «почему», но и **на что это распространяется**:

| Область | Действует на | Когда брать |
|---|---|---|
| **Эта программа** | любой файл с таким именем, подписанный тем же издателем | обновляемые программы — верный выбор по умолчанию |
| **Этот издатель** | все программы этого издателя | если вы ему и так доверяете |
| **Только этот файл** | этот самый отпечаток или путь | разовый файл, который не обновляется |
| **Вся папка** | всё внутри папки, включая то, что положат потом | только если папка ваша |

Это не косметика. Раньше доверие привязывалось только к отпечатку, и для
обновляемой программы оно не работало вообще: `claude.exe` живёт сразу в трёх
местах — в установленной копии, в `.local\bin` и в `WindowsApps` — и после
каждого обновления меняет и папку, и отпечаток. Пользователь жал «Доверять»,
запись сохранялась, а назавтра программа снова оказывалась в находках.

**Области «эта программа» и «этот издатель» опираются на действующую подпись.**
Подделать её, не имея закрытого ключа издателя, нельзя — поэтому доверие не
превращается в дыру. Доверие по одному имени файла стало бы ею немедленно:
достаточно было бы назвать вредонос `claude.exe`. Если подпись отвалится или
файл подменят, доверие перестанет действовать само.

Область **«вся папка»** таких гарантий не даёт и потому предлагается последней
и с прямым предупреждением.

## Активные действия: карантин и завершение

Наблюдения мало, если нечем ответить. В разборе справа у любой находки:

- **Завершить процесс** — закрывает процесс и все его дочерние (сначала потомков,
  потом родителя, чтобы он не успел перезапустить ребёнка). Критические процессы
  Windows (`lsass`, `csrss`, `wininit`, `services`, `smss`, `winlogon`…)
  программа завершать отказывается — это обрушило бы систему.
- **В карантин** — файл не удаляется, а **обратимо прячется**: байты
  переписываются так, что копию нельзя запустить, рядом сохраняется запись с
  исходным путём и хешем. В разделе «Карантин» его можно восстановить
  байт-в-байт или удалить насовсем.
- **Обезвредить** — одно действие: завершить процесс и отправить его файл в
  карантин. Для того, что вы уверенно считаете вредоносным.

Все три спрашивают подтверждение. Карантин обратим; завершение процесса — нет
(несохранённые данные пропадут), поэтому и подтверждение.

## Постоянная защита (сторож)

Входит в автозащиту; отдельно — переключатель «Постоянная защита» в разделе
«Защита». Ставит две задачи Windows:

- **Сторож** — запускается при старте системы (от SYSTEM), работает без окна,
  показывает тревоги во всплывающих уведомлениях, и **перезапускается, если его
  завершат**. Следит за тем, что ломают первым делом: при включённой автозащите
  возвращает каждую её часть; если выключили защиту в реальном времени и другого
  антивируса нет — бьёт тревогу. Один сторож на компьютер: второй экземпляр
  сразу выходит.
- **Наблюдатель** — раз в минуту проверяет сердцебиение сторожа и поднимает его,
  если тот пропал.

Галка **авто-карантин**: если включить, сторож сам изымает файлы, которые
VirusTotal уже знает как вредоносные (5+ детектов). Порог высокий, чтобы не
трогать чистое. Остальное — только с вашего подтверждения в окне.

### Честно о пределе

Настоящие антивирусы грузятся раньше всего (ELAM-драйвер) и защищают себя от
завершения (protected process). И то, и другое даёт **только драйвер,
подписанный Microsoft** — а подпись требует сертификата и процедуры, которых у
самодельной программы нет. Поэтому:

- сторож запускается рано (при старте системы, от SYSTEM) — но не «раньше ядра»;
- он переживает обычное завершение и сам поднимается — но противник, уже
  получивший права SYSTEM и целенаправленно сносящий именно его, победит.

Это честный потолок userland-программы. Обещать неубиваемость, которой нет, —
значит дать ложное чувство защиты, а это хуже, чем честно назвать границу.
Поэтому главный совет прежний: **держите Defender включённым**, а этот сторож —
второй рубеж, который видит то, во что Defender не смотрит.

## Как понимать находки

**Находка — это «необычно», а не «вирус».**

Инструмент намеренно подозрителен. Он поднимет шум на самодельном скрипте, на
программе без подписи от маленького разработчика, на портативной утилите из
Загрузок. Это цена чувствительности.

Порядок разбора:

1. **Узнаёшь программу?** Ставил сам, помнишь зачем — скорее всего всё в порядке.
2. **Не узнаёшь?** SHA256 → VirusTotal (кнопка внизу).
3. **Процесс ЧИТАЛ содержимое базы cookie и это не браузер** — вот это разбирай
   всерьёз, независимо от подписи. Обрати внимание: «менял права доступа» и
   «читал содержимое» — разные вещи, программа их различает.

**Чего инструмент не умеет:**

- не видит руткит уровня ядра;
- не найдёт кражу, случившуюся до установки, если не осталось следов;
- не защитит от расширения, которому ты сам выдал права (но покажет его);
- не заменяет антивирус — дополняет.

## Если кража уже случилась

1. **Отключи ноутбук от сети.** Украденные cookie бесполезны, пока не переданы.
2. **Не перезагружайся сразу** — сохрани папку `evidence\`.
3. **С ДРУГОГО устройства** смени пароли и, главное, **заверши все активные
   сессии** в настройках безопасности каждого аккаунта. Смена пароля без
   завершения сессий не помогает: украденная cookie продолжает работать.
4. Включи двухфакторную аутентификацию везде, где её нет.
5. Только потом разбирайся с самой программой.

## Если что-то не включается

Раздел **Защита** → **Разобраться, что мешает**. Проверяет предпосылки и
называет причину, а не просто повторяет «не получилось»:

- права администратора;
- доступен ли `auditpol` и включена ли подкатегория аудита;
- не перекрывает ли настройки групповая политика (тогда включённое
  возвращается в «выключено» при следующем `gpupdate`);
- найдены ли вообще файлы браузеров — аудит ставится на них, и если
  браузер ни разу не запускали, ставить его не на что;
- журнал безопасности, служба планировщика, политика выполнения,
  доступность папки данных;
- **кто защищает компьютер**: зарегистрированные антивирусы, запрет
  Defender политикой, защита от подделки, служба `WinDefend`.

Последнее важнее, чем кажется. «Защита в реальном времени не включается»
почти всегда означает одно из четырёх, и действия у них разные:

| Что нашлось | Что это значит |
|---|---|
| работает сторонний антивирус | так и должно быть: двум антивирусам в реальном времени вместе нельзя, Defender уступил место |
| сторонний зарегистрирован, но не работает | защиты может не быть вовсе — Defender уступил, а тот не запущен |
| `DisableAntiSpyware` в политике | переключатель не удержится: политика выключает защиту заново |
| включена защита от подделки | настройки Defender нельзя менять ни программой, ни реестром — только руками |

## Язык интерфейса

Окно бывает русским и английским: «Защита» → «Интерфейс» → «Язык интерфейса ·
Interface language». Выбор запоминается в `state\language.txt`, новый язык
включается после перезапуска окна (кнопка «Перезапустить» появляется сама).

Переводится только то, что видно. Внутри находки остаются русскими: заголовок
находки — ключ доверия, поэтому доверенное не теряется при смене языка. Журнал
программы всегда ведётся по-русски. Имена файлов, программ и папок не
переводятся — они такие, какие есть на диске.

## Обновление

Раздел **Защита** → **Версия программы**. Кнопка **Проверить** спрашивает
GitHub, вышла ли новая версия; **Обновить** заменяет файлы программы.

Источник: <https://github.com/SpawRon/CookieGuard>, ветка `main`. Репозиторий
открытый, поэтому ключ доступа не нужен — на втором компьютере достаточно
нажать «Проверить».

Обновление **никогда не ставится само** — только по кнопке. Причина простая:
самообновляющаяся программа это канал, по которому на компьютер приезжает
код, и для инструмента безопасности такой канал — слишком заманчивая цель.
Что сделано, чтобы канал был узким:

- запросы идут только на `api.github.com` по HTTPS;
- архив распаковывается в новую пустую временную папку, и **ничего из
  него не запускается** — файлы только копируются;
- перед заменой проверяется, что внутри действительно CookieGuard
  (`CookieGuard.ps1`, `lib\Core.ps1`, `lib\Checks.ps1`), а не произвольный архив;
- рабочие данные не трогаются: эталон, доверенные, карантин, журналы,
  отчёты, улики и ключ VirusTotal остаются на месте;
- устаревшие модули из `lib\` убираются, чтобы старая логика не лежала
  рядом с новой.

Остаётся доверие к самому репозиторию — и это честная граница: кто получит
доступ к нему, получит и все компьютеры, где нажмут «Обновить».

Если репозиторий приватный, нужен ключ доступа GitHub (кнопка **Ключ
GitHub**, достаточно прав «только чтение»). Ключ лежит в `state\github-token.txt`,
закрыт `.gitignore` и наружу уходит только на `api.github.com`. Для открытого
репозитория ключ не нужен.

Запущенный `CookieGuard.exe` Windows заменить не даст — это не беда, он
только запускает `CookieGuard.ps1`, в котором вся логика.

После обновления ничего перезапускать руками не нужно: окно перезапускается
само, сторож перезапускается сразу на новой версии. Если обновление пришло
мимо окна, сторож сам замечает, что код сменился, и в течение минуты
поднимается на новом коде. Настройки, журналы, летопись событий и копия hosts
обновлением не трогаются.

## Файлы

```
Setup.cmd                установка в систему
CookieGuard.exe          запуск программы
CookieGuard.ps1          окно программы
CookieGuard.ico          значок
scripts\Install.ps1      установка с ключами (-Path, -Autostart, -DesktopShortcut)
scripts\Uninstall.ps1    полное удаление
scripts\Guard-Service.ps1  головной сторож (фоновый, без окна, от SYSTEM)
scripts\Watchdog.ps1     наблюдатель, поднимает сторожа
scripts\Install-*.ps1    включить части защиты (Uninstall-*.ps1 — выключить)
scripts\Scan.ps1         консольная проверка без окна
scripts\Guard.ps1        консольный монитор
scripts\CookieGuard.cmd  запуск без .exe (запасной путь)
lib\                     модули: проверки, монитор, агенты, сеть, доверие, интерфейс
adblock\                 расширение-блокировщик для Chrome, Edge и Brave
build\                   исходник CookieGuard.exe (C#), манифест, генератор значка
docs\                    это руководство и картинки
logs\ reports\ evidence\ state\ quarantine\ cache\   данные компьютера (не в git)
```

Все проверки — только чтение. В системе меняются лишь политики аудита и метки
аудита на файлах браузеров; всё отменяется кнопкой «Выключить».

## Личные данные

Программа ничего о вас не отправляет. Единственное исключение — кнопки, которые
вы нажимаете сами: поиск в интернете, VirusTotal (уходит только отпечаток
SHA256, файл — никогда) и «Спросить у ИИ» (готовит текст и кладёт в буфер
обмена, отправляете вы).

Папки `state`, `logs`, `reports`, `evidence` содержат сведения именно о вашем
компьютере, включая ключ VirusTotal. Они закрыты `.gitignore` — **не выкладывайте
их в публичный репозиторий.**
